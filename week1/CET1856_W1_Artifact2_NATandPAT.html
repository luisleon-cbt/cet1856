How the exam asks this

NAT generates four reliable question patterns. Learn to recognize them on sight.

Pattern 1: which NAT type?

Keyword mapping: server reachable from the internet → static NAT • pool of public addresses, first come first served → dynamic NAT • many hosts, one public address or overload → PAT. PAT is what virtually every real network (and your home router) runs.

Trap: dynamic NAT does NOT share addresses. One host holds one pool address until it times out. Sharing = PAT only.

Pattern 2: the vocabulary question

Decode in two steps: first word = whose host (inside/outside), second word = seen from where (local = the inside view, global = the internet view). The pair the exam tests hardest: inside local = the private address; inside global = its public translation.

Trap: "the address of the inside host as seen by the outside world" = inside GLOBAL, not outside anything.

Pattern 3: how PAT tells sessions apart

Hundreds of hosts share one public address because PAT appends a unique source port to each translation: 203.0.113.5:4001, :4002, :4003. The return packet's destination port is what routes it back to the right inside host.

Trap: "how does PAT distinguish between sessions?" The answer is port numbers, never MAC addresses or VLANs.

Pattern 4: the broken NAT checklist

When NAT "does not work," the exam expects this order: are ip nat inside and ip nat outside on the correct interfaces? Does the ACL match the inside addresses? Does the pool or interface overload statement exist? Verify with show ip nat translations and show ip nat statistics.

Trap: an empty translation table does not mean NAT is broken: translations only appear AFTER matching traffic flows.
