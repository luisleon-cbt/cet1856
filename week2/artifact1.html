How the exam asks this

ACL questions follow four reliable patterns. Learn to recognize them on sight.

Pattern 1: first match wins, and the invisible last line

Processing is strictly top to bottom, and it stops at the first match. Any packet that reaches the end unmatched hits the implicit deny any that every ACL silently carries. A deny entry placed BELOW a permit that already matches the same traffic never fires.

Trap: "the ACL has only permit statements, so why is some traffic dropped?" The implicit deny at the end drops everything unmatched.

Pattern 2: wildcard mask math

Wildcard = 255.255.255.255 minus the subnet mask. So /24 gives 0.0.0.255, /26 gives 0.0.0.63, /22 gives 0.0.3.255. Zero bits must match; one bits are ignored. host equals wildcard 0.0.0.0, and any equals 0.0.0.0 255.255.255.255.

Trap: subnet masks offered where a wildcard belongs. If an ACL option shows 255.255.255.0 as the mask for a /24, it is wrong: ACLs take 0.0.0.255.

Pattern 3: placement strategy

Standard ACLs (1-99) see only the source, so they go close to the destination: placed near the source they would kill traffic to everywhere. Extended ACLs (100-199) match source, destination, protocol, and port, so they go close to the source and drop unwanted traffic before it crosses the network.

Trap: the reversed pairing. "Standard near source" and "extended near destination" are the planted wrong answers.

Pattern 4: applying the list, two different commands

On an interface: ip access-group 110 in (or out). On the vty lines, protecting access to the device itself: access-class 10 in. Named ACLs are edited by sequence number, which is why modern configs prefer them.

Trap: ip access-group on the vty lines, or access-class on an interface. Each command belongs to exactly one place.
