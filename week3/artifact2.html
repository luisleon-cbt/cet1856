VPNs, AAA & QoS

Three ideas that finish the security picture: how VPNs carry private traffic over a public internet, how AAA controls who may do what, and how QoS keeps a voice call clear while a backup saturates the link. Learn each one hands-on, then switch to Test Prep.

1. VPN explorer

A VPN builds an encrypted tunnel across the public internet. Click each term, then compare site-to-site against remote access.
SITE-TO-SITE VPNTwo routers (or firewalls) build a permanent tunnel between whole networks. Users at each site never know it exists: the gateways do all the encryption. This is how a branch office reaches headquarters over the internet.Exam angle: site-to-site = gateway to gateway, always on, transparent to users. Remote access = one user's device to the gateway, on demand.

How the exam asks this

These three topics each have a reliable question pattern.

Pattern 1: which VPN type?

branch office permanently connected to HQ or gateway to gateway means site-to-site. a traveling employee's laptop connecting on demand means remote access (SSL/TLS or client-based). Both use IPsec concepts; the difference is who builds the tunnel and when.

Trap: "transparent to end users" always means site-to-site. Remote access requires the user to start the connection.

Pattern 2: the two security guarantees

A VPN provides confidentiality (encryption hides the data) and integrity (hashing proves it was not altered), plus authentication of the peers. Keep them straight: confidentiality is secrecy, integrity is tamper-evidence.

Trap: "which service guarantees the data was not modified?" is integrity (a hash), not confidentiality (encryption).

Pattern 3: the three A's, in order

who are you is authentication. what are you allowed to do is authorization. what did you do is accounting. The order never changes: prove, permit, log. RADIUS and TACACS+ are the servers that provide AAA centrally.

Trap: authorization vs authentication. "The user logged in but cannot run a command" is an authorization problem, not an authentication one.

Pattern 4: QoS vocabulary

Classification identifies traffic, marking tags it (voice as EF, DSCP 46), and queuing/scheduling decides who goes first. Voice cares about low latency and low jitter; it would rather lose a packet than wait. Default behavior with no QoS is FIFO: first in, first out.

Trap: "voice needs high bandwidth" is the weak answer. Voice needs LOW, PREDICTABLE delay far more than raw bandwidth.
