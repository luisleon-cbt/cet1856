How the exam asks this

Layer 2 and wireless security produce four reliable question patterns.

Pattern 1: the violation modes table

All three modes drop frames from unknown MAC addresses. protect: drops silently. restrict: drops, logs, and increments the counter, the port stays up. shutdown (the default): the port goes err-disabled, recovered with shutdown then no shutdown. sticky is not a mode: it makes learned MAC addresses persist in the running config.

Trap: "the port is down and the config shows port-security" is err-disabled from a shutdown violation. Recovery is shut, then no shut.

Pattern 2: snooping trust and the binding table

DHCP snooping marks every port untrusted by default: server-only messages (OFFER, ACK) arriving on an untrusted port are dropped, which neutralizes a rogue DHCP server. The port toward the legitimate server or uplink gets ip dhcp snooping trust. As leases flow, snooping builds the binding table of IP, MAC, port, and VLAN.

Trap: forgetting to trust the real server's port blocks legitimate DHCP too. "Snooping on, nobody gets a lease" means a missing trust statement.

Pattern 3: DAI depends on snooping

Dynamic ARP Inspection validates each ARP packet's IP-to-MAC pairing against the DHCP snooping binding table. No snooping, no table, no DAI. That dependency is the tested fact.

Trap: "enable DAI alone to stop ARP poisoning" fails, because the binding table does not exist until snooping runs first.

Pattern 4: the wireless decision tree

one shared passphrase is PSK (personal). per-user credentials / RADIUS / 802.1X is Enterprise. SAE handshake / protection against offline dictionary attacks is WPA3. WEP and WPA (TKIP) appear only as the broken answers.

Trap: WPA2-Enterprise is not a stronger cipher than WPA2-PSK. The difference is AUTHENTICATION (802.1X per user), not encryption.
